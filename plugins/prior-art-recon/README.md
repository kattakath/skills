# prior-art-recon

Before building, standardising or publishing anything meant to fill a perceived gap, answer one
question first: **is the gap real, and should it be filled?** Those are two questions, and the
second kills more ideas than the first.

```
can it be killed? --> terrain map --> where was it decided? --> direction of travel --> verdict
```

Five lanes, each able to end the project. The lane most likely to earn its keep is the one that
finds the thing already exists.

## The four ways a real gap is still the wrong thing to fill

| | |
|---|---|
| **Direction** | the gap is real, but the ecosystem is moving away from it |
| **Doctrine** | a principled argument against this approach, held by people with standing |
| **Alternative** | a different mechanism already achieves the same end |
| **Artifact** | the gap exists only because of how *you* built the thing you are building |

The **Artifact** case is the highest-value finding: the deliverable is not "stop" but *the
assumption that created the gap, the design change that dissolves it, and what that costs.*

## What it returns besides the verdict

The **terrain map** — every standard, body, regulation and tool the space touches, *including the
dead ends*, because you cannot search for what you cannot name. And **where the decision was
actually argued**: commit messages, review threads, governance votes — not documentation.
Documentation states conclusions; commits state reasons, and name who disagreed.
